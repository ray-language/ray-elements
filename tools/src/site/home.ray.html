Everything an app needs

From the form on the login screen to the command palette of a desktop tool — one set of components, one set of tokens, in any stack.

Web standards

Custom elements with Shadow DOM. Form fields are form-associated, overlays use the Popover API and the native dialog. No framework required.

React & Vue

Generated wrappers with typed props and events, v-model in Vue, and editor data for VS Code. The elements stay the single source of truth.

Tokens first

One tokens.toml becomes CSS variables and JSON. Contrast is checked against WCAG AA at build time; the chart palette is also checked for color blindness.

Theming

Light and dark with light-dark(), 13 palette colors as primary, any brand color with definePrimary, and per-component defaults with configure.

Own the code

Copy the components you need into your app with add, like shadcn/ui, or install the npm packages. Plain JavaScript, no build step.

Extensible

Build your own components on RayElement: properties, styles, icons and form behavior come with it, and wrap generates their types and wrappers.

Same element, any stack

Write HTML, or use the generated wrappers. Events, forms and refs behave the same.

Works anywhere. Extras in raylang.

Nothing in a component requires raylang. In a raylang app, ray-elements loads from ray://app with no build step, and its tokens, docs, packages and browser tests are generated by raylang tools.

No build step

ES modules straight from ray://app in a std/ui window, form fields that hand a FormData to the program, and example apps checked in the real webview.

Native bridge

File dialogs with real paths, the app's menus in the command palette, native context menus and confirm dialogs, and the window chrome: title bar, colors that follow the theme, the unsaved-changes mark.

One package

The elements dependency brings the bridge and serves @raylang/elements to the pages by its npm name, from the app binary, with no npm install.
